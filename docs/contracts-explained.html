Why this matters

Contracts are the project's single critical blocker

3
Contract schema change = 3 components must rebuild. Payment Processing (Component #21), Percentage Rent & Sales (#22), ASC 842 Accounting (#23) all consume the contract schema. A late change cascades through every downstream test corpus and journal-entry math. That's why ADR-0008 freezes the schema at week 12.

In Lx today

Lucernex contracts — what firms see now
  • 2,823 fields under the "Contract" top group across ~95 sub-areas
  • Payment Transaction is the biggest sub-group (117 fields)
  • Contract Info, Expense Setup, % Rent Breakpoints, Covenants are the spine
  • Wizards exist, but they don't enforce a flow — analysts can enter things out of order
  • Vendor, accounting, and payment setup live in separate modules — no "is this contract ready to pay?" status

In ASG Edge+

The new platform — what BRD-24 mandates
  • One connected contract record from intake through first rent
  • Wizard-driven setup — atomic creation, no partial shells
  • Workflow is the abstraction path: kick-off → abstractor → QA → client → close
  • Auto-assigns ASG + client users from org chart at creation (FR-011/012)
  • Status lifecycle: Open → Active → Possession → Paying Rent → Closed (FR-010)
  • All changes audit-logged with who, what, when, why (FR-029)

The single rule

If the contract schema is wrong, everything downstream is wrong

W12
Schema-freeze deadline. ADR-0008. After week 12, changes to the contract schema must be additive only — new columns, new tables, never breaking changes. Because every financial feature (payments, % rent, ASC 842) reads from this schema, and rewriting their test corpora in Phase 4 would blow the timeline.
